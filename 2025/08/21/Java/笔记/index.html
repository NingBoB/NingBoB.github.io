volatile

简述：volatile用于同步机制中。在多线程中线程访问共享变量时，需要保障共享变量的一致性和可靠的更新，在Java中，提供volatile来实现该互斥访问和同步更新。

1.作用

1.保证变量的可见性

volatile在进行访问变量时跳过了CUP的缓存，直接读取内存中的值，这个值是最新且相同的。

2.保证赋值操作的原子性

如果变量声明为volatile，那么虚拟机会保证赋值是原子的，是不可被打断的。

3.禁止指令重排

正常情况下，虚拟机会对指令进行重排，当然是在不影响程序结果的正确性的前提下。volatile可以在一定程度上禁止虚拟机进行指令重排，这样就可以对实现读写顺序的保证。

为什么要防止指令重排：例如new关键字在编译的时候会生成四条指令：new、dup、invokespecial、astore。

其中new开辟堆空间，并指向该对象，dup复制栈顶的对象，invokespecial会消耗一个对象地址，调用构造函数，astore将初始化好的对象引用赋值给变量。

因此若invokespecial和astore两个指令发生了重排，那么会有可能得到一个未定义的值，即先获取了对象的引用，但是值为空。

使用volatile可以防止指令重排，保证执行顺序。

synchronized锁的是谁？

1.特性

‘synchronized’关键字在java中用于实现线程同步，它主要保证了：

  • 互斥性：同一时间只有一个线程可以访问目标代码块或者方法，解决了多线程同时访问共享资源带来的问题。
  • 可见性：线程的操作结果对其他的线程是可见的。
  • 有序性：保证了线程之间的执行顺序。
  • 原子性：保证操作的原子性，同一时间只有一个线程可以访问资源。

2.对不同目标加锁

下面的讨论可能有点问题，因此重新总结一下：

protected修饰的方法可以被同一包下的子类和子类对象进行访问；不同包下，子类中可以访问，但是无法通过创建任何其他子类来调用protected方法。

其中静态protected方法在同一包下，无论是否为子类，都可以直接访问；但是在不同包下非子类无法直接访问。

实验

先思考几个问题：

  • 同一个包中， 子类对象能访问父类的 protected 方法吗？

可以

  • 不同包下， 在子类中创建该子类对象能访问父类的 protected 方法吗？

可以

  • 不同包下， 在子类中创建父类对象能访问父类的 protected 方法吗？

不能

  • 不同包下， 在子类中创建另一个子类的对象能访问公共父类的 protected 方法吗？

不能

  • 父类 protected 方法加上 static 修饰符又会如何呢？

和上述的规则相同

1.实践

1.同一个包中， 子类对象访问父类的 protected 方法

结果：可以访问

2.不同包下， 在子类中创建该子类对象访问父类的 protected 方法；

可以访问

3.不同包下，在子类中创建父类对象访问父类的 protected 方法

不能访问

错误提示：

‘setMessage(java.lang.String)’ has protected access in ‘learn.protectedSign.pkg1.Parent’

4.不同包下， 在子类中创建另一个子类的对象访问公共父类的 protected 方法

同样无法访问，错误提示同上。

5.父类 protected 方法加上 static 修饰符

添加了static后，在子类中可以直接访问， 在不同包的非子类中则不可访问。

总结：protected关键字的目的是**限制方法只能在当前的类中使用**，若子类继承了父类，则该子类也具有父类的protected方法，因此可以访问，但是无法通过在子类中创建父类或者其他地方创建子类或父类的方式访问。

内部类以及静态内部类

关于“java中静态内部类的设计意图”的理解 - 知乎 (zhihu.com)

为什么会有内部类：一个类只能继承一个具体类或抽象类（但是可以实现多个接口）。没有多继承是因为在多继承中，多个父类中的重复属性或方法会出现歧义。

而使用内部类的原因是：每个内部类都能进行继承 ，所以无论外围类是否已经继承，对于内部类都没有影响。

1.成员内部类

成员内部类也是最普通的内部类，它是外围类的一个成员，所以它可以无限制的访问外围类的所有成员属性和方法，而外围类要访问内部类的成员属性和方法则需要通过内部类实例（创建对象） 来访问。需要注意：

  • 写在成员位置的，属于外部类的成员。
  • 成员内部类可以被一些修饰符所修饰，比如：private，默认，protected，public，static等。
  • 成员内部类里面，JDK16之前不能定义静态变量，JDK16开始才可以定义静态变量

静态内部类与非静态内部类之间存在一个最大的区别：非静态内部类在编译完成之后会隐含地保存着一个引用，该引用是指向创建它的外围内，但是静态内部类却没有。

关于继承

  • 子类继承了父类的全部，但是子类不能直接访问父类的私有方法或属性

  • 在父类中定义了一个有参构造，那么原来的无参构造就会被​覆盖。此时若父类没有无参构造（不自己定义），那么在子类继承的时候，其构造方法中需要使用super(父类构造参数)，指定使用的父类的有参构造器。在分析代码的时候需要注意默认的super()

  • 多层次的继承访问属性/方法有这样的规则：

    • 直接访问
      • 首先看子类是否有该属性
      • 如果子类有这个属性，并且可以访问，则返回信息
      • 如果子类没有这个属性，就看父类有没有这个属性（如果父类有并且可以访问，就返回信息；若遇到了private被阻塞，那么就不会继续了）
      • 以此类推，直到找到Object
    • 使用this访问
      • 和直接访问一样
    • 使用super访问
      • 直接在父类访问

  • 在继承的过程中，子类通过构造函数的方式创建了一个父类的对象，通过方法的重写和调用父类方法，可以让子类拥有更多的扩展方法。

关于this

  • 可以使用this.方法名(参数列表) ;的方式访问成员方法
  • 可以使用this(参数列表) 的方式访问构造器，但是只能在构造器中使用
  • 在构造器中使用需要放在构造器代码中的第一行，这与super()相同，因此两者只能出现一个，有了super就没有this，有了this就没有super

关于super

  • 可以访问父类的属性和方法，但是不能直接访问私有的属性和方法
  • 访问父类的构造器必须在第一行出现，且只能出现一句这样的访问

关于“==”的判断

“==”可以用于判断值相等和对象相等。在判断基本数据类型的时候比较值；在判断对象相等的时候，比较的是对象的地址，常见的易混淆Inteager对象和int基本类型。

equals()是所有对象的一个方法，只能用于判断引用类型是否相等，默认判断地址是否相等。

在其子类中通常会重写这个方法，用于判断内容是否相等，例如Inteager和String类型。但是会在判断值相等之前利用‘==’或者‘instanceof’来判断类型是否相同。

2.字符串的不可变性

String类是由final修饰的（无法被继承），保存字符串的是一个f​**inal​修饰的​私有**char/byte类型的数组。

在Java中，字符串是不可变的，创建一个字符串会在字符串池（String Pool）来缓存字符串值，任何对字符串的修改操作都会生成一个新的字符串对象，赋值操作将会改变其地址指向的内存空间，而原始的字符串对象保持不变。这种不可变性有着一些重要的好处：

  1. 线程安全：不可变的字符串可以在多个线程中安全共享，而不需要额外的同步措施。
  2. 缓存：Java内部使用字符串池（String Pool）来缓存字符串字面值，这样可以重复使用相同的字符串，节省内存。
  3. 安全性：不可变字符串在安全性方面有优势，因为它们无法被修改。
  4. 性能优化： 编译器可以对不可变字符串进行各种优化，从而提高性能。

守护线程，线程设置为守护线程后会在主线程结束后就结束。在主线程关闭后，无需手动关闭守护线程，因为它会自动关闭，这可以避免一些问题。Java垃圾回收线程就是一个典型的守护。

所有为线程服务而不涉及资源的线程都能设置为守护线程。

yield()方法

礼让线程，调用该方法后放弃调度权，进入RUNNABLE状态。线程只是暂时的将调度权让给别人，但立刻可以回到竞争线程锁的状态，这是与sleep()方法不同的地方，sleep()方法会让线程进入TIMED_WAITING状态，等待指定时间后进入RUNNABLE状态。

join()方法

将某个线程插入当前的线程中，若将某个线程插入后，该线程会优先执行，执行完毕后才会继续执行原来的线程。否则，线程和线程会穿插执行。

线程中断

首先我们需要弄清楚线程的状态有哪些：

  • New：新创建的线程，尚未执行；
  • Runnable：运行中的线程，执行run()方法中的Java代码；
  • Blocked：运行中的线程，因为某些操作被阻塞而挂起；
  • Waiting：运行中的线程，因为某些操作在等待中，等待线程的控制权
  • Timed Waiting：运行中的线程，因为执行sleep()方法正在计时等待；
  • Terminated：线程已终止，因为run()方法执行完毕或者被迫终止。

中断线程的实现方法很简单，通过调用目标线程的interrupt()方法，然后再目标线程中反复检测自身状态是否为interrupted状态，如果是，就立刻结束运行。

其中 t.interrupt()​**只是向t线程发出了一个‘中断请求’** ，至于t线程是否立刻响应，则需要交给具体的代码执行。

Thread类中包含以下用于中断操作的方法：

  • interrupt()：中断一个线程，发送一个请求；
  • isInterrupted()：检查当前线程是否被中断。线程的*中断状态不受此方法的影响*；
  • interrupted()：检查当前线程是否被中断。线程的中​*断状态被此方法清除*。

线程池是一个容纳了多了线程的容器，允许对线程的管理和重复使用，避免了频繁创建和销毁带来的开销，提高系统线程效率的一种技术。
