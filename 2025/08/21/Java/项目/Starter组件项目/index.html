将组件封装为starter组件时需要注意：

  1. 确保starter组件的通用性：在WhiteListAutoConfigure自动配置类中扫描配置文件WhiteListProperties.class，对组件中需要注册的Bean在配置类中进行注入，而不要在WhiteListProperties.class中使用@Component注解。

    因为引入jar包的项目不一定能扫描到（除非包名相同，这几乎不可能，若想使用，则需要在启动类上指定扫描的路径）

  2. 确保配置了正确的META-INF/spring.factories文件，开启自动配置。

服务治理中间件整合—GovernStarter

https://gitcode.net/CreativeAlliance/springbootstarter-chicheng

整合的时候需要注意熔断服务是异步的，因此需要通过@Order()注解将该切面放到最后执行

1. 异步方法的执行和 AOP 的切入顺序

  • AOP 切面通常是在当前线程中执行的。它会在目标方法被调用之前或之后拦截并执行逻辑。
  • 如果目标方法是一个异步方法（如 @Async），这个方法会立即返回，而实际的业务逻辑会在另一个线程中执行。由于切面通常是同步的，它可能会在异步方法执行之前已经返回了，导致页面空白或者数据未能正确返回。

2. 问题的原因

  • AOP 切面执行提前返回：异步方法调用时，AOP 可能在异步方法返回之前就已经完成了处理，导致页面没有等待异步方法执行完成，造成页面展示为空。
  • 线程不一致性：异步方法会被提交到不同的线程执行，而 AOP 是在当前线程上运行的。这样，AOP 中的某些上下文（如事务管理、请求上下文等）可能没有正确传递到异步线程中。
  • 缺少线程同步：AOP 切面没有等待异步任务执行完成，导致页面请求已返回而异步任务还在执行。
