大营销怎么做的？

使用redis缓存库存数量，用户抽奖时，先通过责任链的方式判断当前的抽奖操作（判断包括：是否是黑名单用户、用户积分是否达标）确定用户的奖池，然后执行抽奖。

获取奖品后，进一步对奖品进行校验（库存检查、用户抽奖次数是否达标），这里使用到了规则树的设计模式，最终确定用户抽奖获得的奖品。

库存扣减过程中，通过责任链的方式对活动进行校验。成功后对缓存中的库存进行扣减，并通过Redisson中的setNx的方式为库存数量加锁，并设置过期时间，若上述的操作成功（但是存在少买的问题，未解决，但不会出现超卖），则通过mq消息的方式异步更新数据库（优化：当缓存库存为0时，直接清空消息队列，并发送数据库库存置零的消息）。

mq异步处理：

将秒杀和下单、支付分开来，后面两个操作一般都有一个完成的时限

消息丢失问题：设置消息发送表，设定消息状态，通过状态判断是否需要重发（job重试机制）

重复消费问题：设置消息处理表，订单生成之前判断是否存在未消费的订单，不存在则下单，并写将订单写入消息处理表。

垃圾消息问题：记录消息发送次数，限制发送次数

延迟消费问题：延迟队列，实现在延迟时间达到后通知对订单进行状态检查（需要在15分钟内支付）

延迟队列

限流处理：用户id限流、ip限流、接口限流、验证码

‍

限流中的漏桶和令牌桶

令牌桶：设置桶的容量，以固定的速度往桶里放入令牌，达到容量后不再放入。令牌桶在空闲时会累积填充，一定程度上可以缓解突发容量带来的影响。用于保护自身系统。

漏桶：以固定的速度发放令牌，不能累积，绝对匀速。无法处理突发流量。用于保护下游系统。
