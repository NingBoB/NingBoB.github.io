Java虚拟机栈

什么是虚拟机栈？

  1. 虚拟机栈是每一个线程在运行时所需要的内存，是先进后出的；

  2. 每个栈（每一个线程都会创建一个对应的虚拟机栈）由多个栈帧组成，对应每次方法调用时所占用的内存（保存了参数、局部变量、返回地址等）；

  3. 每个线程只能有一个活动栈帧，对应线程当前正在执行的任务。

方法内的局部变量是否线程安全？

若局部变量没有逃离方法作用范围，则是线程安全的，否则，若变量需要返回或者是形参，则可能不安全。

栈内存溢出的情况

栈帧过多导致，例如递归操作。

循环依赖导致。

栈帧？

局部变量表、操作数栈、动态链接、程序返回地址

本地方法栈

保存一些本地的native方法，也包含了栈帧，和虚拟机栈类似

程序计数器

实现代码的流程控制，多线程环境下用于线程切换时保存当前执行的位置。唯一一个不会OOM

Java堆

介绍一下Java的堆

  1. 线程共享的区域，主要用于保存对象、数组等，包含了字符串常量池，内存不足会抛出OOM异常
  2. 由年轻代和老年代组成，其中年轻代包含Eden区和两个大小严格相同的Survivor区；老年代主要保存生命周期长的对象。
  3. 对象进入老生代的年龄阈值，可以根据JVM参数 ​-XX:MaxTenuringThreshold​ 来设置。
  4. 1.7中将字符串常量池从永久代（hotspot）中移动到了堆中，其目的是为了便于gc管理。

Java中的堆是线程共享的区域，其中用于保存创建的对象，包含了字符串常量池（1.7以前是在永久代中，1.7移动到了堆中）。堆内存被分为了新生代和老年代，其中新生代又被分为3个区域，一个eden区和两个大小相同的Survivor区。对象创建后将被保存在新生代区域，GC发生后，根据垃圾回收算法，会将存活的对象进行移动，可能还会对内存空间进行移动。经历了GC后仍然存活且达到了年龄阈值的对象将被移动到老年区。

为什么要分为新生代和老年代？

依据对象的特点划分，分别使用不同的垃圾回收算法，提高垃圾回收的效率。

字符串常量池：StringTable

1.7之前在永久代实现的方法区中；1.7之后在堆中

为什么移动？永久代的GC效率太低，full GC的时候才会回收，放在堆中可以灵活回收

Java方法区：

永久代和元空间都是方法区的一种实现。

hotspot JDK中，1.8之前，永久代位于jvm内存空间中，1.8之后元空间位于直接内存中。

元空间中有哪些内容？

方法区是各个线程共享的内存空间，主要存储类的信息（元数据）、运行时常量池、静态变 量；

其中类的信息指的是类的元数据，类的方法代码，变量名，方法名，访问权限，返回值等等都是在方法区的。

元数据并不是class对象，class对象是类加载的最终产品，它**存放在堆区**

虚拟机启动时创建，关闭时释放；

常量池与运行时常量池的关系？

常量池是.class文件中的，类似一个指令字典，在方法的机器指令是通过在查找常量池中查找指令来执行的。

​

类加载过程中，在解析阶段，它的常量池信息就会放入运行时常量池，并将里面的符号地址变为真实的内存地址。

类加载器

别翻了，这篇文章绝对让你深刻理解java类的加载以及ClassLoader源码分析【JVM篇二】

什么是类加载器，类加载器有哪些？

JVM只会运行二进制文件，类加载器的作用就是将字节码文件加载到JVM中，从而让Java程序能够启动起来。

用户自定义类加载器、应用程序类加载器、扩展类加载器、启动类加载器。

什么是双亲委派模型？

类加载器加载某一个类，每次都会将其不断委托给上一级的加载器进行加载，若最后启动类加载器都没有加载，则该类加载器才会尝试自己加载。

为什么使用双亲委派机制？

  1. 可以避免某一个类被重复加载，父类加载过了则由父类加载，保证唯一性
  2. 为了安全，保证类库API不会被修改。下层若定义了库类，则不会自己加载，而是由上层的加载器进行加载，这样就可以避免对类库的修改。———–沙箱安全机制。

如何判断两个Java类是否相同？

不仅全类名要相同，加载类的加载器也要相同。

如何打破双亲委派机制？

自定义类加载器的实现需要继承ClassLoader。若不想打破双亲委派机制，则重写其中的findClass()方法即可，当父类无法加载的时候，类会被重写的findClass()加载。

而当我们重写了其中的loadClass方法后，就可以打破双亲委派机制。结合源码即可得知，loadClass中执行步骤如下：

  1. 首先在缓存中查看是否已经加载，不存在则继续执行；
  2. 不存在则交给父类加载器，若父类加载器为null，则表明需要使用启动类加载器；
  3. 向上委托加载均失败，则调用findClass来进行加载；

Tomcat为了能够优先加载Web目录下的类，就通过自定义类加载器WebAppClassLoader来打破双亲委派机制。

为什么Tomcat需要打破双亲委派机制？

参考

因为一个Tomcat可以运行多个Web应用程序，那么需要防止两个程序中具有相同全类名的类产生冲突，因此通过自定义加载类实现优先加载在当前应用目录下的类。

实现了Web应用层级的隔离。

类装载的执行过程？

加载、连接【验证、准备、解析】、初始化、使用、卸载

加载：查找和导入class文件，放入元空间，然后再堆空间中创建对应的class对象

验证：保证加载类的准确性

准备：分配空间。为类变量，即static修饰的，赋给**默认初值，真正的赋值在初始化阶段完成。其中static+final的常量，包括基本类型和字符串常量在准备期间进行赋值**；static+final的引用类型，赋值在初始化阶段完成。

类中有类变量和类成员变量，其中类变量使用static进行修饰，在准备阶段会为其分配空间，赋给默认初值；而对于类成员变量，则是在初始化阶段进行赋值；其中final修饰的类变量会直接赋值，因为其不可变性。

解析：把类中的符号引用转换为直接引用，就是放入运行时常量区

初始化：对类的静态变量，静态代码块执行初始化操作。用户定义的代码会在这个阶段执行。

初始化一般是产生对类的​**主动使用**才进行的：

  • new对象
  • 访问类或接口自己的静态变量
  • 调用类的静态方法
  • 反射
  • 子类初始化，父类也会初始化
  • 带有main函数的类会被初始化，或者启动类

在静态调用中，只有被调用的静态值所在的类，即自己的， 才会被初始化，例如子类继承父类后通过子类（不是new）直接访问父类的静态变量，那么**只有父类会执行初始化**。

此外直接访问**final修饰的类变量**（编译器确定的，必须是常量，函数调用这种就不行）也是不会进行初始化的，因为它在准备期间已经有值了，可以直接访问。

区分类初始化方法和对象初始化方法：

前者包括了静态变量和静态代码块；

后者包括了代码块、构造函数、成员变量；

在分析代码调用语句执行顺序的时候，需要关注是类还是对象的初始化。

堆内存分配和回收的原则

垃圾回收触发？

空间分配担保机制

新对象的创建会分配到新生代中的Eden区域，若此时新生代的Eden区​空间不足，则会触发MinorGC（需要注意是Eden区满了才触发，S0和S1满了不会触发；GC过程中需要考虑空间分配担保机制，即确保老年代还有足够的空间）。

JDK6之后的**空间分配担保机制**，在Minor GC的时候会触发，首先会判断老年代是否有足够的空间可以分配新生代中的所有对象：

  • 空间充足，则直接进行Minor GC

  • 空间不足，则预估老年区中是否可以分配之前GC迁移的平均空间大小：

    • 可以，则进行Minor GC
    • 不可以，则进行Full GC

根据不同的垃圾回收器，大的对象会直接被放入老年区

GC后，长期存活的对象将被放入到老年区（15次）

GC分类？

GC可以分为两类：

  • 部分GC：

    • Minor GC（对新时代）
    • Major GC（对老年代）
    • Mix GC（整个新时代和部分老年代）

  • Full GC（新时代、老年代和方法区）

对象回收的判别依据

如何判断一个对象什么时候可以被回收？

如果一个对象**没有任何引用指向**它了，那么这个对象是垃圾，需要被回收。

判断对象是垃圾的方法有哪些？

引用计数法（循环引用问题）

可达性分析算法（GC Root）

哪些对象可以作为可达性分析法中GC Root？

虚拟机栈中引用的对象（局部变量中的对象）：在方法中，定义局部变量，该变量可以作为GC root，当方法执行结束后，该变量指向的对象就会被回收。

本地方法栈中的引用的对象：

方法区中类静态属性引用的对象、常量引用的对象：这些静态变量和常量与类加载器是绑定的，其作为GC root时，当对应的类加载器被销毁了，那么这些变量若没有其他的引用，那么指向的对象将被回收。

四种引用和GC之间的关系？

强引用：不会被GC回收，即使OOM了也不会

软引用：空间不足的时候，会在GC发生前进行回收，否则不会回收

弱引用：GC的时候就会回收

ThreadLocal内存泄漏问题—key是弱引用，但是ThreadLocalMap对Entry是强引用，发生了垃圾回收，key就会被回收，此时Entry就产生了一个null指向的value，该value永远无法被访问到。 这部分空间会持续存在，直到线程关闭，Entry被回收后，才会回收，这就导致了内存泄漏问题。

ThreadLocal存储的数据格式是一个Map，即ThreadLocalMap，JDK1.8之后，存在如下的对应关系：

  • Thread中保存着ThreadLocalMap；
  • ThreadLocal对象作为ThreadLocalMap中的key，存入的值或对象作为value；

内存泄漏的问题需要进一步查看ThreadLocalMap的内部：

Map自定义了一个Entry，并将其中的key也就是ThreadLocal对象设置为弱引用，GC的时候就会被回收，那么Entry中就存在一个null指向的value，Entry与线程是强引用的，若不主动回收，那么只有线程结束了这片空间才会被回收，进而导致了内存泄漏问题。

该问题在线程池中尤为明显，因为其中的核心线程是共享的，不会频繁销毁，会出现脏数据问题和内存泄漏。

​

总之，Entry的key被设计为弱引用就是为了让程序自动的对访问不到的数据进行回收提醒，所以，在访问不到的数据被回收之前，内存泄漏确实是存在的，但是我们不用担心，就算我们不调用remove()，ThreadLocalMap在内部的set（发生冲突），get和扩容时都会清理掉泄漏的Entry，内存泄漏完全没必要过于担心。

将key设置为弱引用可以避免key因为Entry存在而无法被回收，同时为value引用提供一个可移除条件，即key为null，但是value不为null的情况需要移除value；

而value不能被设置为弱引用，因为它的创建可能不是强引用，若设置为弱引用，那么GC的时候就会删除，此时若key还存在强引用而没有被回收（即还有用），那么就会取到null。

ThreadLocal对象作为key，由线程本身控制回收，而value是我们设置的，由我们来决定回收。

虚引用：任何时候都可以被回收

如何判断一个类可以被回收？

该类的实例都被回收、加载该类的类加载器都被回收、对应的Class对象没有引用

垃圾回收算法

垃圾回收算法有哪些？

标记清除算法：标记，根据可达性分析算法对垃圾进行标记，然后对这些内容进行回收。

优点：标记和清除速度较快；

缺点：碎片化较为严重，内存不连贯

标记整理算法：标记回收后将存活的对象移动到一端。（适合老年代）

复制算法：内存空间分为两半，标记回收，然后将存活的移动到另一半内存空间。（年轻代）

优点：无碎片

缺点：内存使用率低

分代回收算法：根据不同区域的对象存活的特点，采用不同的回收策略。

讲一下JVM中的分代收集算法机制

新生代由于每次GC的时候会有大量的对象被回收（朝生夕死），因此可以采用复制算法进行回收；

而老年代的对象存活时间更长，可以使用标记-清除或者标记-整理的算法进行回收。

新生代的to和from区域依次进行存活对象的复制，将Eden和其中一块中的存活对象复制到另一块中，然后清除Eden和其中一块中的全部对象。

当对象的复制操作达到了一定的次数（最多15次），或者提前升级（内存不足或者大对象），就会复制进入老年代

MinorGC、Mixed GC、FullGC的区别是什么？

MinorGC：新生代中发生的垃圾回收，导致短暂的STW

Mixed GC：新生代+老年代的部分区域的垃圾回收，G1收集器特有

FullGC：新生代和老年代完整的垃圾回收，长时间的STW，应当避免

JVM有哪些垃圾回收器？

串行垃圾回收器

并行垃圾回收器（JDK8默认）

CMS（并发）垃圾回收器：并发、标记清除算法、针对老年代【初始标记、并发标记、重新标记、并发清除】

G1垃圾回收器：应用在新生代和老年代之间，在JDK9之后默认使用

划分为多个大小相同的区域：eden，survivor，old，humongous（大对象），每个区域并不固定

复制算法

兼顾响应时间和吞吐量

三个阶段【初始标记、并发标记、最终标记、筛选回收】、并发失败会触发FullGC

强引用、软引用、弱引用、虚引用的区别

强引用：通常的代码中，例如A a = new A()，除非GC Root不再指向，否则不会被回收，即使发生了OOM。

软引用：在垃圾回收后，内存仍然不足，系统发生内存溢出前会进行回收，User user = new User(); SoftReference softReference = new SoftReference(user);​

弱引用：WeekReference w = new WeekReference(user);仅有弱引用引用该对象时，在垃圾回收时，无论内存是否充足，都会进行回收。

‍

虚引用：处理引用对象（堆内存中）之外的内存对象（例如直接内存中的引用），称之为虚引用对象。将这部分对象放到虚引用队列中，引用对象回收后释放内存。
