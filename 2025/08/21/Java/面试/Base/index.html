为什么说 Java 语言“解释与编译并存”。

编译型语言：将源程序一次性编译成特定平台（操作系统）可以运行的机器码。编码效率低，执行效率高。

解释型语言：将源程序逐行翻译成特定平台的机器码并执行。编码效率高，执行效率低。

Java将程序编译成中间码，即class文件，然后在其运行时进行编译。

Java泛型、类型擦除

泛型

关于Java泛型，它可以实现将类型参数化，主要的实现有泛型类、泛型接口和泛型方法。

泛型的使用在具体对象创建的时候指定了数据类型，当在使用的时候，必须要传入与指定类型相匹配的参数，提供了一种类型安全检测的机制。

泛型类的实现有很多，例如List和ArrayList都使用了泛型来实现在对象创建的时候定义类型。

泛型接口的类型参数在其被继承或者被实现的时候确定，也可以接着定义泛型类，需要保证泛型类型相同。

泛型方法的参数是在调用方法的时候传递的，注意泛型方法中的泛型必须是显示定义的，与类中的泛型不同，例如public <E> void show_3(E t){}。

总结：

  1. 泛型的使用提供了类型扩展的能力，更加符合面相对象的特性、提供了类安全检测机制、程序的可读性提高；
  2. 类中的静态成员不能定义为泛型，而静态方法可以；
泛型类型擦除

类型擦除指的是在编译期间，编译器会擦除代码中的所有泛型语法并完成一些类型转换。因此在运行的时候是没有泛型的信息的。

擦除的过程实现的是类型转换，默认泛型的父类为Object，那么在擦除的时候就会将泛型类型替换为Object。但是若是形如的泛型，其父类就是Number，泛型擦除的时候会替换为Number。

总结：

  1. 泛型信息只在编译期间存在，编译期间执行擦除，运行期间没有泛型信息。
  2. 类型擦除后，运行期间若要使用对象的信息，编译器底层会进行自动类型转换，转换为指定的泛型的类型。

泛型通配符—界限约束

泛型之间是*没有向下转型的概念*，即可以创建List a = new ArrayList() ，但是不能创建List<Number> a = new ArrayList<Integer>()（意图实现Number包容其子类Integer）；

但是在实际应用中，存在一个方法需要处理多种类型的泛型参数，即想要实现一个方法，同时可以接收Integer和Number类型。因此引入了泛型通配符来解决这个问题。

我们在方法中使用泛型类型的时候也可以不指定其具体的泛型，而是可以在调用的时候指定，在方法定义中使用泛型通配符。

泛型通配符有 3 种形式：

  1. <?> ：被称作无限定的通配符。
  2. <? extends T> ：被称作有​**上界​的通配符，内小外大，取出来可以向上转型，但是放进去不行。**
  3. <? super T> ：被称作有​**下界​的通配符，外小内大，父类都可以放进去，但是取出来只能是Object，不能向下转型。**
